# 05 · 问题清单与迭代记录

> 本文档记录项目开发过程中出现的**真实问题、定位过程、解决方案与当前状态**，
> 包含已解决项、已知局限项与后续优化方向。用于支撑「失败案例 / 问题清单」的留存要求。

## A. 已解决问题

### A1 中文数据编码导致读取乱码
- **现象**：直接以 UTF-8 读取原始 CSV 在第 397 字节即抛 `UnicodeDecodeError`；若误用 `latin-1` 兜底，中文列全部变成乱码。
- **定位**：原文件编码为 **GB18030**；`latin-1` 对任意字节序列都能「解码成功」，会抢答。
- **解决**：实现 `detect_encoding()` 逐个试探候选编码，并把 `latin-1` 排到最后且增加「含高位字节则跳过」的规则；
  数据源配置中显式记录编码，导入报告输出实际使用的编码。
- **状态**：已解决（编码探测结果记录在数据版本的 `ingest_report.encoding`）。

### A2 一次性载入 58MB 文件存在内存风险
- **现象**：初版 `pd.read_csv()` 全量载入，峰值内存高，与「大数据技术」定位不符。
- **解决**：改为 `chunksize` 分块迭代读取（默认 20 万行/块），逐块做类型强制与列名规范化；
  引入 `chunk_size` 参数并在版本记录中输出分块次数；另提供 `tools/etl.py split` 把大文件切成分片。
- **状态**：已解决。

### A3 异常值「直接删行」引入选择偏差
- **现象**：把 IQR 判定为异常的样本直接删除，样本量下降明显，且高价豪宅被系统性剔除。
- **分析**：房价长尾是**真实市场特征**而非脏数据，删行会让模型低估高价区域。
- **解决**：改为「截断修复」——把越界值置为列中位数，保留样本；同时输出每列的检出数、上下界与修复动作。
  对确实违反业务区间的记录（如单价 < 3000 元/㎡）则由 `range` 策略处理。
- **状态**：已解决（并提供 `none / iqr / zscore / range` 四种策略供对比实验）。

### A4 特征泄漏风险
- **现象**：`total_price` 与目标 `unit_price` 存在确定性关系（`total_price = unit_price × area / 10000`），
  若作为特征会使 R² 虚高到 0.99+，属于典型标签泄漏。
- **解决**：建立 `FORBIDDEN_FEATURES` 黑名单并在特征构造末尾用 `assert` 强制校验，
  校验结果写入版本记录的 `feature_report.forbidden_check`。E3 消融实验进一步量化各特征组的真实贡献。
- **状态**：已解决。

### A5 随机切分高估模型性能
- **现象**：随机切分下 HGB 的 R² 明显高于时间切分。
- **分析**：随机切分把**同一小区、同一时期的相邻成交**同时放入训练集与测试集，
  测试样本的近邻已在训练集中出现过，属于信息泄漏。
- **解决**：默认采用**时间切分**（训练=早期，测试=后期），并把两种协议的差异做成 E2 对比实验。
- **状态**：已解决。

### A6 协同过滤缺少用户 ID
- **现象**：公开数据集只有成交记录，没有用户标识，无法构造真实的「用户-房源」交互矩阵。
- **分析**：这是数据本身的硬限制，不能通过算法绕过。
- **解决**：
  1. 协同过滤使用**参数化行为模拟日志**——用户画像（偏好区域/面积/价格/户型）从真实数据分布采样，
     加入一定比例随机探索项；整个过程由固定随机种子驱动，协议与种子写入实验记录，**完全可复现**；
  2. 显式在 API 返回、前端提示与文档中声明「该指标用于算法间相对比较，不代表线上绝对值」；
  3. 额外设计**只依赖真实成交记录**的评估协议（相似房源检索：相关性 = 同小区 且 单价差 ≤10%），
     使推荐模块至少有一部分指标建立在真实数据上。
- **状态**：部分解决（已如实声明并给出替代评估方案，仍属数据局限）。

### A7 全量相似度矩阵内存不可行
- **现象**：候选房源 30 万条，构造 item-item 相似度矩阵需 900 亿元素。
- **解决**：利用「余弦相似度按用户历史求和可分解」的性质：
  `score_j = Σ_{i∈I_u} cos(i,j) = v · Mn[:,j]`，其中 `Mn` 为列归一化（含收缩系数）的隐式反馈矩阵。
  一次稀疏矩阵-向量乘法即可完成全量打分，复杂度降到 `O(nnz)`。
- **状态**：已解决。

### A8 长任务导致请求超时 / 前端假死
- **现象**：完整流水线需 1–3 分钟，训练树模型需 10–60 秒，同步 HTTP 请求会超时，用户误以为系统崩溃。
- **解决**：引入线程池任务队列（`backend/jobs.py`），接口立即返回 `job_id`；
  前端每 1.5 秒轮询 `/api/jobs/{id}`，实时显示阶段进度与最终结果；失败时展示错误与链路信息。
- **状态**：已解决。

### A9 仪表盘查询慢
- **现象**：概览页需要区域统计、趋势、直方图、相关性、散点、地理点等十余类聚合，
  若每次请求都全表扫描 30 万行，首屏加载缓慢。
- **解决**：在流水线末尾增加**批处理汇总阶段**，一次性算出 11 类预聚合结果，
  同时写入 SQLite `agg_*` 表与 JSON 快照；前端只读预聚合结果，响应降到毫秒级。
- **状态**：已解决。

### A10 网络带宽受限导致的数据获取缓慢
- **现象**：数据集 58.4MB，在受限网络下下载速率约 40KB/s，且连接偶发被中断（`schannel: server closed abruptly`）。
- **解决**：使用 `curl -C -` 断点续传 + 重试循环；同时提供「先暂停下载、让依赖安装优先占用带宽」的操作顺序建议；
  数据源配置支持 `local_csv`，离线环境可手工放置文件。
- **状态**：已绕过（工程手段而非根治）。

### A11 IQR 异常值处理把长尾变量压成了常数（重要）
- **现象**：首次跑通流水线后检查 `days_on_market`，发现该列 min=5、max=8、标准差 0.1 —— 整列几乎退化成常数。
- **定位**：初版 `handle_outliers` 对所有数值列做 IQR 截断，并把越界值置为**列中位数**。
  `days_on_market`、`followers` 是**重尾计数型**变量：四分位区间很窄（如 IQR≈55，而中位数为 29），
  于是 IQR 上界（约 148）之下的样本虽保留，但大量长尾值被压到中位数，导致分布被严重扭曲。
- **影响**：该列作为特征已失去区分度，等于白送一个常数特征。
- **解决**（两项一起改）：
  1. **收窄检测范围**：新增 `schema.OUTLIER_COLUMNS`，异常值检测只针对业务连续量
     （单价、总价、面积、小区均价、建成年份、梯户比），不再对重尾计数量做截断；
  2. **改变处置动作**：新增 `outlier_action` 参数，默认 `winsorize`（把越界值**封顶到边界**，保留排序信息），
     另提供 `clip_median`（原行为）与 `drop`（删行）供对比实验选择。
- **验证**：改造后 `days_on_market` 恢复真实的右偏分布；模型测试指标一并改善（见 E5 实验）。
- **状态**：已解决。

### A12 `community_avg_price` 存在跨期尺度漂移（重要）
- **现象**：时间切分下，模型在测试集上的表现明显差于预期；单独用 `community_avg_price` 做一元回归时，
  在**测试期内**可解释 79.6% 的方差，但把训练集拟合的系数搬到测试集上，R² 掉到 **-1.05**。
- **定位**：对比两期的统计量发现——训练期（2002–2016）样本的 `unit_price` 均值为 38,026，
  而 `community_avg_price` 均值为 63,701（比值 0.60）；测试期（2016–2018）两者均值分别为 62,921 与 62,302（比值 1.01）。
  也就是说该字段**相对于成交价存在明显的时间尺度不一致**（很可能是上游按不同时点快照统计的），
  使得「小区均价 → 成交单价」的映射关系随时期漂移。
- **影响**：
  - 依赖该字段的树模型在时间切分下泛化受损，而这恰恰是它最重要的特征；
  - 直接导致测试集 R² 从「理论上可达 0.8」降到 0.2–0.4 区间。
- **处置**：
  1. 在本项目中**如实保留该特征并如实报告结果**，不通过随机切分掩盖问题；
  2. 特征消融实验（E3）单独量化「去掉小区均价」的影响；
  3. 新增 `feature_profile` 档位（`no_community` / `compact`）供研究者对比；
  4. 尝试「相对价格」目标变换（`unit_price / community_avg_price`）来消除漂移——实验表明**本数据集上收益有限**，
     因为漂移发生在特征与目标的**关系**上，而非目标的绝对水平上（见 E1 对比结果）。
- **状态**：已定位并在文档中如实声明，作为已知局限（B8）；属于上游数据质量问题，无法在建模层根治。

### A13 时间特征反而损害树模型的泛化（重要迭代）
- **现象**：E3 消融实验出现反直觉结果——把 `trade_year / trade_month / trade_quarter` 三个时间分量
  从特征集中**移除**后，梯度提升树的测试 R² 从 0.210 提升到 0.434，RMSE 从 17,090 降到 14,458。
- **定位**：树模型只能输出训练集**已见取值区间**内的分段常数预测，本质上不具备外推能力。
  训练集覆盖 2002–2016，测试集是 2016–2018；模型在 `trade_year` 上分裂后，
  只能把训练期末段的水平照搬到测试期，反而把训练期的周期模式"记死"。移除时间分量后，
  模型转而依赖小区均价、房屋结构等更稳定的**截面特征**，泛化反而更好。
- **对比**：线性模型可以外推，因此移除时间分量对它略有损失（R² 0.268 → 0.243），
  这从另一个侧面印证了「树模型不能外推」这一判断。
- **处置**：把结论固化为可复用配置 `schema.FEATURE_PROFILES`（`full` / `no_time` / `no_community` / `compact`），
  前端「模型训练」页可直接切换并对比，无需改代码。
- **状态**：已解决，并转化为系统功能。

### A14 `drop` 缺失值策略造成样本选择偏差，指标虚高（重要）
- **现象**：E4 实验里，把缺失值策略从「中位数填充」切换为「删除含缺失行」后，
  最终数据量从 318,200 条降到 152,002 条（**损失 52%**），但测试集 R² 从 0.209 **暴涨到 0.8928**，
  RMSE 从 17,097 降到 7,175，MAPE 从 22.85% 降到 8.99%。看上去「删掉缺失数据」是个巨大的胜利。
- **定位**：逐列统计缺失后发现，`days_on_market` 的缺失**强烈依赖成交年份**：

  | 年份 | 缺失率 | | 年份 | 缺失率 |
  | --- | --- | --- | --- | --- |
  | 2011 | 85.5% | | 2015 | 60.8% |
  | 2012 | 85.2% | | 2016 | 29.4% |
  | 2013 | 81.9% | | 2017 | 2.8% |
  | 2014 | 85.0% | | 2018 | 0.9% |

  该字段在 2015 年之前基本没有系统化记录。执行 `dropna()` 等价于**把 2011–2014 年删掉约 85%**，
  保留数据的时间跨度从 2002–2018 压缩为「2010–2018，且 60% 集中在 2015 年以后」。
  于是训练集与测试集在时间上变得非常接近——E2 中揭示的**分布漂移被"人为消除"了**。
  指标上升与「缺失值处理得更好」毫无关系，而是**把困难的时间外推任务变成了容易的时间插值任务**。
- **影响**：如果只比较指标，会得出「drop 策略更优」的错误结论，并让系统用一份被时间截断的数据去建模。
- **解决**：
  1. 默认策略保持**中位数填充**，保留全部样本与完整时间跨度；
  2. 在 E4 实验记录、前端与文档中显式标注该策略存在**时间截断风险**；
  3. 把这个案例写进「失败案例」章节，作为「指标提升 ≠ 方法更优」的实证。
- **状态**：已定位并如实记录。

### A15 对目标变量做统计截断等于"改标签"（重要）
- **现象**：异常值处理最初把 `unit_price`（预测目标）也纳入了 IQR 处理范围。
  实测 IQR 上界为 **92,477 元/㎡**，导致 **11,751 条（3.7%）真实高价成交**被统一压成同一个数值；
  同时在直方图上表现为最后一个分箱出现异常尖峰（前端「数据概览」页肉眼可见）。
- **定位**：`schema.OUTLIER_COLUMNS` 把目标变量和特征变量混在一起处理了。
  对**特征**做统计截断是标准做法；但对**标签**做截断，等于告诉模型
  「这套 15 万元/㎡ 的房子真实价格是 9.2 万元/㎡」——这不是清洗，是**篡改监督信号**。
  后果：模型在最贵的那部分房源上被要求预测一个被人为改写的值，该区间的误差评估也失去意义。
- **量化对比**：修正前后，同一个 HGB 配置的测试指标从 R²=0.209/RMSE=17,090（截断目标）
  变为 R²=0.341/RMSE=19,576（保留真实目标）。后者指标更差，但**前者是假的**。
- **解决**：
  1. 从 `OUTLIER_COLUMNS` 中**移除 `unit_price`**；
  2. 目标变量的异常处置改为**业务区间硬过滤**（`TARGET_BUSINESS_RANGE` = 3,000–200,000 元/㎡），
     在 `filter_records` 阶段**剔除**而非改写（共剔除 651 条脏记录）；
  3. 在清洗报告中新增 `target_policy` 字段说明该策略；
  4. E5 实验重新对比后证实：在业务列上各异常值策略的差异 < 1%，
     此前看到的巨大差异其实全部来自目标截断。
- **状态**：已解决。

## B. 已知局限（如实声明，不掩盖）



| 编号 | 局限 | 影响 | 缓解方式 |
| --- | --- | --- | --- |
| B1 | 无用户 ID，协同过滤依赖模拟日志 | CF 指标不代表线上效果 | 声明 + 真实数据相似度检索作为补充 |
| B2 | 数据止于 2017-02 | 结论不能外推到当前市场 | 所有结论限定在样本期内 |
| B3 | 类别编码语义不完全透明 | 部分特征语义存疑 | 保留 `未知` 兜底，不臆测；映射集中可替换 |
| B4 | 缺朝向、学区、楼层实际层数等因子 | 模型存在系统性高估/低估区间 | E7 失败案例诊断量化偏差分布 |
| B5 | 树模型局部归因为近似方法 | 单样本归因只能看方向 | 结果中显式标注 `method` 字段说明近似性 |
| B6 | 未做分布式（Spark）实现 | 单机内存仍是上限 | 采用分块扫描 + 列存 + 预聚合，为替换为分布式实现预留了接口边界 |
| B7 | 无线上 A/B 实验 | 推荐效果缺在线验证 | 离线多指标对比 + 覆盖率约束 |
| B8 | `community_avg_price` 存在跨期尺度漂移 | 时间切分下模型 R² 受限在 0.2–0.45 | 已在 A12 中定位并如实报告；提供 `no_community` 特征档位对比；属上游数据质量问题 |
| B9 | 时间切分下整体 R² 偏低（0.2–0.45） | 不能用于精确估值 | 如实报告 MAE/MAPE 与误差带命中率；给出预测区间而非单点值 |

## D. 后续优化方向

1. **接入真实用户行为埋点**，用真实交互替换模拟日志，使协同过滤指标具备线上参考价值；
2. **引入小区固定效应 / 目标编码**，缓解「同小区内可比性」带来的残差结构（对应 E7 诊断结论）；
3. **时间序列建模**：用滚动窗口 + 时序交叉验证替代单次时间切分，量化模型的时间稳定性；
4. **分布式化**：将分块扫描替换为 Spark / Flink 作业，`store.py` 的输出契约保持不变；
5. **推荐在线化**：引入多路召回 + 排序模型（GBDT ranker），并用 A/B 实验验证；
6. **数据管道调度**：把 `tools/etl.py` 挂到 cron / 计划任务，实现周期性增量更新与版本滚动。
